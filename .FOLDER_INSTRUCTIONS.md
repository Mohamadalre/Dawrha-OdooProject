## 👥 SYSTEM ROLES & PERMISSIONS (من الأهم للأقل)

### 1. **Admin** (الإدارة العامة)
- ✅ عرض جميع المستودعات والبيانات العامة
- ✅ قبول طلبات الموظفين (إدخال/فرز/إخراج/صيانة)
- ✅ إسناد المستودعات لمديري المستودعات
- ✅ عرض إحصائيات النظام الكاملة
- ✅ إدارة الوظائف والتوظيف
- ✅ رفع تقارير المعدات من مدير المستودع

### 2. **Warehouse Manager** (مدير المستودع)
- ✅ الوصول **فقط** لمستودعه المسند
- ✅ قبول طلبات الموظفين (إدخال/فرز/إخراج/صيانة) من قائمة الانتظار
- ✅ إسناد الأدوار لموظفيه (Sorting/Output/Maintenance)
- ✅ متابعة الورديات والحضور والغياب
- ✅ تقارير المعدات والصيانة
- ✅ مراجعة طلبات الصيانة من موظف الفرز
- ✅ تحويل حالة المعدة (إصلاح/استبدال/إخراج الخدمة)
- ✅ عرض إحصائيات مستودعه فقط
- ✅ تصدير التقارير للطلبات

### 3. **Input Employee** (موظف الاستقبال)
- ✅ استقبال الشحنات (مسح باركود أو إدخال يدوي)
- ✅ عرض معلومات الشحنة
- ✅ تسجيل الوزن الفعلي للشحنة
- ✅ رفع الشحنات في حالة اختلاف كبير للمدير
- ✅ إدخال الشحنات لمنطقة الاستقبال (Zone: Receiving)
- ✅ عرض الشحنات التي عالجها هو
- 🚫 لا يرى شحنات الموظفين الآخرين المحجوزة

### 4. **Sorting Employee** (موظف الفرز)
- ✅ عرض الشحنات غير المحجوزة في منطقة الاستقبال
- ✅ حجز الشحنة (حصري للموظف)
- ✅ فرز المواد وإدخال الكمية والجودة (ممتاز/جيد/تالف)
- ✅ نقل الشحنة لمنطقة المفرز (Sorted Zone)
- ✅ كتابة تقرير المعدات (حالتها وتفاصيلها)
- ✅ إرسال التقرير لمدير المستودع
- 🚫 لا يرى الطلبات (Orders)

### 5. **Output Employee** (موظف الإخراج)
- ✅ عرض الطلبات غير المسندة من الباك إند
- ✅ حجز الطلب (حصري للموظف)
- ✅ عرض تفاصيل الطلب (المواد والكمية والعميل)
- ✅ تخصيص المواد من المخزن
- ✅ خصم الكمية تلقائياً من Stock
- ✅ نقل المواد لمنطقة الإخراج (Output Zone)
- ✅ إنشاء فاتورة PDF (السعر حسب Role العميل)
- ✅ عرض الطلبات التي عالجها هو
- 🚫 لا يرى الشحنات (Shipments)

### 6. **Maintenance Employee** (موظف الصيانة)
- ✅ متابعة طلبات الصيانة من مدير المستودع
- ✅ تحديد حالة المعدة (تشغيل/رفض)
- ✅ تحديث حالة الطلب (Accepted/Rejected)
- ✅ تحديث حالة المعدة (Working/Out of Service)
- ✅ تحديد السبب في حالة الرفض
- 🚫 لا يرى بيانات أخرى

## 🎯 WORKFLOW CHECKLIST

### **Receiving Workflow** (موظف الاستقبال)
```
1. [ ] Scan QR Code OR Enter Shipment ID
2. [ ] Display shipment details (products, quantities, weight)
3. [ ] Enter actual weight (weigh on scale)
4. [ ] Check weight variance:
   - If > 2% difference: Alert manager, mark as "needs_review"
   - If ≤ 2% difference: Accept
5. [ ] Move shipment to Receiving Zone
6. [ ] Update shipment state to "accepted"
```

### **Sorting Workflow** (موظف الفرز)
```
1. [ ] View available shipments (not reserved)
2. [ ] Select shipment → Reserve (state = "sorting")
3. [ ] Enter product quantity + quality (excellent/good/damaged)
4. [ ] Update stock in Storage Zone
5. [ ] Create equipment maintenance report
6. [ ] Submit report to manager
7. [ ] Move shipment to Sorted Zone (state = "sorted")
```

### **Output/Order Workflow** (موظف الإخراج)
```
1. [ ] View available orders (from backend API, not reserved)
2. [ ] Select order → Reserve (state = "processing")
3. [ ] Display order details (products, quantities, customer)
4. [ ] Check Stock availability
5. [ ] Allocate products from Storage Zone
6. [ ] Deduct quantity from Stock (automatic)
7. [ ] Move products to Output Zone
8. [ ] Generate Invoice PDF (price based on customer role)
9. [ ] Mark order as "delivered"
```

### **Maintenance Workflow** (موظف الصيانة)
```
1. [ ] Receive maintenance request from manager
2. [ ] Review equipment issue & maintenance report from sorting employee
3. [ ] Check if equipment is operational:
   - If YES: Update status = "accepted", equipment state = "working"
   - If NO: Update status = "rejected", note reason
4. [ ] Send response back to manager
5. [ ] Manager escalates to admin for replacement/disposal decision
```

## 🔧 DEVELOPMENT BEST PRACTICES

### Backend (Python)
- ✅ Use `@api.depends()` for computed fields
- ✅ Implement `_compute_*` methods (not direct assignments)
- ✅ Use record rules for row-level security (in security.xml)
- ✅ Validate data with `_check_*` methods
- ✅ Use `ir.rule` domain filters (NOT hardcoded ORM filters)
- ✅ Log important actions for audit trail
- 🚫 Never hardcode warehouse or user access

### Frontend (JavaScript/Owl)
- ✅ Fetch data from controllers (dashboard_api.py, api.py)
- ✅ Use Chart.js for dynamic charts (NO hardcoded data)
- ✅ Calculate percentages dynamically: `(value / total) * 100`
- ✅ Support Light/Dark mode CSS variables
- ✅ Use Tailwind CSS (no inline styles)
- ✅ Handle loading/empty states
- 🚫 Do NOT hardcode any data

### Views (XML)
- ✅ Use `groups=` attribute to hide fields per role
- ✅ Use dynamic domains for filtering data
- ✅ Add view-level security checks
- 🚫 Do NOT use `<data noupdate="1">` for security-sensitive data

## 📝 TRANSLATION WORKFLOW

When adding **new UI text**:

1. **Python models**: Wrap with `_("text")`
2. **XML views**: Use `<string>text</string>` tags
3. **JavaScript**: Add to `recycle_i18n_shared.js`
4. Generate translation template:
   ```bash
   ./manage.py makemessages
   ```
5. Translate in `i18n/ar.po` and `i18n/en.po`
6. Update template files with translations

## 🆘 TROUBLESHOOTING

**Q: "Permission Denied" on shipment/order?**
→ Check `ir.rule` domain in security.xml matches user's warehouse

**Q: Data showing from other warehouse?**
→ Verify `domain_force` in record rule uses `warehouse_id` or manager relationship

**Q: Chart data not updating?**
→ Ensure controller returns fresh calculated data, not cached values

**Q: Arabic text showing garbled?**
→ Verify UTF-8 encoding in Python files (`# -*- coding: utf-8 -*-`)
